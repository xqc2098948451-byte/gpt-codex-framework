# GPT–Codex Framework v2.2.1 Self-Hosting and Publication Corrective Design

## Scope and fixed compatibility boundary

This is a forward-only corrective patch from the accepted v2.2.0 baseline. It
adds only the two audited fixes: Framework Management self-hosting validation
and mechanical publication-authority enforcement. `KERNEL_VERSION` remains
`2.0.0`, `SCHEMA_VERSION` remains `1`, and the frozen v2.2.0 artifact and its
SHA-256 remain immutable.

The work is local-only. It may produce implementation commits and v2.2.1
artifacts, but it must not perform GitHub writes or alter existing remote
history.

## A. Framework Management self-hosting validation

The project validator accepts the management-only dual-root profile exactly
when `CONTROL.framework_management_only == true`,
`CONTROL.governance_profile == FRAMEWORK_MANAGEMENT`,
`roots.project_role == AUTHORITATIVE`, and
`roots.framework_role == SELF_MANAGED`. Ordinary consumers continue to require
the normal `MINIMAL`/`STANDARD`/`EXTENDED` profile and
`framework_role == ADVISORY`; management labels alone do not weaken those
rules.

An enabled management extension may omit `installed_path` only when it is a
builtin and its ID is present in the Framework Built-in catalog with a valid
catalog entry and manifest. This is a narrow self-hosting exception, not a
general builtin exemption.

## B. Publication authority invariants

The Result Envelope contract and its validator reject every contradictory
combination:

- `status == PASS` requires `remote_verification == VERIFIED`.
- `sync_status == SYNCED` requires verified publication evidence.
- `publication_authority == PUBLICATION_CANDIDATE_ONLY` cannot coexist with
  `PASS`, `SYNCED`, or authoritative `COMPLETE` state.
- authoritative `COMPLETE` requires a durable Result/Evidence reference that
  satisfies the verified publication gate.
- `STATE.continuity.sync_status == SYNCED` requires a non-empty
  `latest_verified_remote_sha` tied to verified evidence.

JSON Schema v1 expresses the conditional fields that are reliable to express;
Python validators enforce cross-document and evidence semantics that require
inspection of Result/Evidence records.

## C. Verified-baseline and attestation semantics

Publication remains the existing bounded W/P model. Work commit W contains the
generic v2.2.1 source, release metadata/artifacts, and pre-publication
management state. Before any PASS attestation is created, W must be remotely
verified. Publication/attestation commit P may then durably attest the verified
W SHA with `PASS`, `SYNCED`, and `VERIFIED`; P never claims its own SHA and
never contains a self-reference.

Before W is verified, local completion is represented as
`LOCAL_COMPLETE`/`SYNC_PENDING` with candidate authority and a non-final
verification/reconciliation state. A final PASS/SYNCED/COMPLETE result is not
valid in that phase.

## D. Forward-only recovery and resume

The current historical contradiction is treated as an invalid historical claim,
not rewritten. The local corrective revision may enter
`RECONCILIATION_REQUIRED` or `VERIFYING` and remains `SYNC_PENDING` because
this work unit is not authorized to publish.

Resume distinguishes the verified generic baseline W from the current
attestation head P. `remote main == P` is valid when P is management-only, P
references reachable verified W, and P has no generic Framework drift. An
unreachable W or generic-source drift requires reconciliation.

## E. Confirmed-baseline-only GitHub publication policy

All local tests, validators, packaging, and release checks may run, but this
work unit ends with `GITHUB_WRITE_PERFORMED = NO`, `PUSH_STATUS = NOT_ATTEMPTED`,
and `SYNC_STATUS = SYNC_PENDING`. A later, separately authorized publication
work unit is required after GPT accepts the clean v2.2.1 baseline.

## F. Release and verification boundary

Version metadata, CHANGELOG, README/governance references, release index,
release record, and current-only v2.2.1 distribution artifacts are updated.
The release ZIP must exactly match the generic Framework source except for the
documented management CONTROL/STATE/evidence/result exclusions and local Git
metadata exclusions. The final verification includes the frozen v2.2.0 SHA,
Kernel byte comparison, Schema generation check, full unittest suite, framework
and project validators, release integrity/hygiene, and unchanged remote HEAD.
