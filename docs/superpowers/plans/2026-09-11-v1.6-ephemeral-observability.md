# v1.6 Ephemeral Observability & Runtime Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add project-parameterized, worktree-scoped ephemeral observability and durable runtime-verification summaries without weakening existing Git/parallel/bootstrap governance.

**Architecture:** Extend the framework adaptation model with observability defaults/parameters, add an observability artifact directory and result template, and wire runtime verification through task, execution, state, handoff, review, parallel, Codex rules, and bootstrap guidance. Raw telemetry remains ephemeral; concise verification evidence is durable.

**Tech Stack:** Markdown governance templates; LogQL/PromQL as default compatible query interfaces; provider-agnostic tracing.

**Spec:** `docs/superpowers/specs/2026-09-11-v1.6-ephemeral-observability-design.md`

## Global Constraints

- Preserve all v1.5.1 capabilities and historical specs/plans.
- Observability is configurable per project; framework invariants remain non-overridable.
- Production/external persistent telemetry requires separate explicit authorization.
- Raw telemetry defaults to ephemeral; verification summary is durable.
- Parallel telemetry is isolated by worktree/task/unit/run identity.
