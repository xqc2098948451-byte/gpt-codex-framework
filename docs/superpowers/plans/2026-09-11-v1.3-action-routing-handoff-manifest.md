# GPT–Codex Framework v1.3 Action Routing & Handoff Manifest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add explicit GPT action routing and a durable derived handoff manifest so users always know where to execute instructions and which artifacts to give GPT.

**Architecture:** Keep `PROJECT.md` authoritative for project definition and `STATE.md` as the current-state index. Add `HANDOFF.md` as a lower-authority derived navigation artifact and add mandatory executor labels for all GPT-issued actionable steps. Integrate both protocols into bootstrap, implementation, review, resume, and compact-return paths.

**Tech Stack:** Markdown governance files and templates; ZIP distribution.

**Spec:** `docs/superpowers/specs/2026-09-11-v1.3-action-routing-handoff-manifest-design.md`

## Global Constraints

- Universal framework version becomes `1.3`.
- Framework migration must not redesign approved business architecture.
- `HANDOFF.md` must never override `PROJECT.md`, approved artifacts, Git evidence, or `STATE.md`.
- Action routes are exactly `USER_LOCAL`, `CODEX`, `RETURN_TO_GPT`, and `INFO`.
- Codex instructions use explicit copy boundaries.
- Default handoff is minimum required evidence; additional evidence is on demand.
