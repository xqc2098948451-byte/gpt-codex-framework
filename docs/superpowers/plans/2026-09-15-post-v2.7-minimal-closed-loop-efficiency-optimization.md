# Post-v2.7 Minimal Closed-Loop Efficiency Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans`, as GPT selects at implementation time. Use test-driven-development for every behavior change, verification-before-completion before completion claims, and requesting-code-review at milestone/risk gates. Do not infer Codex parallelism or agent count from this Plan.

**Goal:** Reduce current and future management cost while preserving every required Framework capability and the existing closed loop.

**Architecture:** Extend existing authorities only: projection classification remains in `consumer_projection.py`, publication checks remain in the publication/release contract, verification remains a skill/Evidence contract, and cleanup decisions remain in `git_continuity.py`. The implementation is sequential: classification first, bounded preflight and evidence rules next, then a decision-only lifecycle rule, a review-only audit, and an integrated preservation gate.

**Tech Stack:** Python 3 standard library, `unittest`, JSON manifests, Git CLI, Markdown skills and maintenance records.

**Design / Spec Authority:** `3b6a206a2db91849384c05e1bb20052afd11688c:docs/superpowers/specs/2026-09-15-post-v2.7-minimal-closed-loop-efficiency-optimization-design.md`.

## Global Constraints

- Every reviewed implementation uses `implementation -> immutable Task SHA -> fresh independent read-only Reviewer context -> GPT adjudication -> ACCEPT or fresh corrective implementation`. Reviewer context differs from Implementer context. Task N+1 cannot begin while Task N has unresolved `CRITICAL` or `IMPORTANT` findings. Reviewer handoff is `BASE_SHA`, `TARGET_SHA`, `DESIGN_REF`, `PLAN_REF`, `GOAL`, `SCOPE`, `CONSTRAINTS`, `DONE`, verification commands, and adjudicated open findings only—never an implementation transcript, private reasoning, or chain-of-thought. `DUAL_CONTEXT_REQUIRED = YES`; `DUAL_WINDOW_REQUIRED = NO`.

- 保留能力，压缩结构；保留闭环，删除重复。
- 真实问题必须闭环到根因；已经由现有能力解决的问题不再新增机制。
- `AFTER_CAPABILITIES >= BEFORE_CAPABILITIES`; Framework module count remains `7`; no eighth module.
- No Kernel version, schema version, or Framework `VERSION` change; a discovered unavoidable schema compatibility issue requires Design and Plan revision before action.
- No release/publication, Git-history rewrite, force push, automatic P0 removal, deletion/merge/derivation without evidence, tracing platform, worktree database, second release subsystem, or private chain-of-thought storage.
- Prior Task-8 nine-candidate `KEEP` decisions remain authoritative unless new evidence proves otherwise.
- `REFERENCE_FIRST`; contamination scanning stays fail-closed; `CONSUMER_REQUIRED` stays explicit exact authority and no prefix can include a consumer file.
- This Plan contains no Context Lifecycle or Handoff Completeness requirement and does not generalize the isolated attachment observation.
