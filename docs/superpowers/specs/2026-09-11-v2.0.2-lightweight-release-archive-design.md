# v2.0.2 Lightweight Release Archive Design

## Goal

Keep framework release history useful without embedding old binary ZIPs into the management source tree or every future release.

## Design

- `VERSION` remains the single framework release-version source.
- `releases/INDEX.json` and `releases/records/v<version>.json` are lightweight metadata.
- Historical ZIP import validates the archive, records SHA-256/size/provenance, and copies no binary into `releases/`.
- `dist/` is transient and contains only the current generated release outputs.
- `framework-release` remains a management-project-local Skill and gains only `releases/` metadata write permission in addition to `dist/`.
- Current ZIP SHA remains external because embedding a final ZIP hash inside the ZIP itself is self-referential.
- Kernel version/schema remain unchanged.

## Safety

Historical artifact deletion never deletes source history or project history. Release records are advisory archive metadata, not a replacement for Git history. Corrupt archives cannot be imported.
