# GPT–Codex Framework v1.4.1 Semantic SHA Fix Design

## Scope

Patch the universal framework only. Do not migrate or modify any downstream project.

## Problem

Framework v1.4 mixes repository HEAD with semantic implementation identity in several derived governance fields. After an implementation commit records its SHA, a later governance-only commit that writes that SHA into TASK/STATE/HANDOFF/REVIEW changes repository HEAD again. Treating HEAD equality as implementation identity can therefore create a self-reference loop and false reconciliation/review-staleness signals.

## Design

1. Separate `Implementation SHA` from `Observed Repository HEAD`.
2. `Implementation SHA` identifies the last commit that changes the task's implementation surface.
3. `Observed Repository HEAD` is informational Git evidence observed at a point in time; it is not an identity requirement for reviewed implementation.
4. Add `State Basis` so STATE can state which implementation SHA and governance observation it was derived from without claiming to contain its own future commit SHA.
5. Classify post-implementation commits by change surface: `IMPLEMENTATION_SURFACE`, `GOVERNANCE_ONLY`, or `MIXED`.
6. A verified `GOVERNANCE_ONLY` commit does not invalidate an implementation review. `IMPLEMENTATION_SURFACE` or `MIXED` changes after the reviewed implementation SHA make that review stale.
7. Git-specific branch/base/HEAD/worktree/change-ownership/review-binding conflicts use `GIT_RECONCILIATION_REQUIRED`; general durable-state conflicts use `STATE_RECONCILIATION_REQUIRED`.
8. Universal framework distributions preserve this framework's own `docs/superpowers/specs/` and `docs/superpowers/plans/` history. Downstream project migration rules are separate and must not be conflated with framework release packaging.

## Governance-only boundary

A commit may be classified `GOVERNANCE_ONLY` only when its actual diff is restricted to approved governance/evidence paths and contains no implementation-surface changes. A mixed diff cannot be relabeled by commit message.

## Review binding

Fresh Review binds to `Task Base SHA..Implementation SHA`. Governance-only metadata that documents the reviewed state may be checked for governance consistency separately without changing the reviewed implementation identity.

## Version

Release as v1.4.1, a patch release of Controlled Git Lifecycle.
