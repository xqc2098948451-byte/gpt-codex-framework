## 1. Proven B7 authority gap

B7 requires one new release Work Unit.  The current Group-B implementation Work
Unit does not own the release Work Unit path or any of the nine B7 release
candidate paths. `NEW_WORK_PREFLIGHT=CLEAN_SYNCED` is only a prerequisite.
Current production validates already-authorized Work Units but has no
authority-bearing production route for creating a new Work Unit JSON. No
existing current authority can create the proposed release Work Unit. Legacy
bridges are not reusable.

This is an authority-cycle closure requirement, not a Task-5–9 production
defect. It preserves the accepted Contract Repair technical semantics and B6
clean-room proof unchanged.

## 2. Frozen future release Work Unit

The future Work Unit is the single bounded object to be materialized only after
the separate governance and bootstrap lifecycle below has completed.

```text
RELEASE_WORK_UNIT_ID = framework-v2.7.3-release-001
RELEASE_WORK_UNIT_PATH = .gpt-codex/work-units/framework-v2.7.3-release-001.json
RELEASE_WORK_UNIT_STATE = AUTHORIZED
RELEASE_WORK_UNIT_BASIS_STATE_REVISION = 16

RELEASE_WORK_UNIT_OWNED_PATH_COUNT = 9
RELEASE_WORK_UNIT_EXCLUDED_PATHS = []
```

If State revision changes before bootstrap execution, `RECONCILIATION_REQUIRED`.
There is no silent rebase of `basis_state_revision`.

Its owned paths are exactly:


It must not own its own JSON path, `.gpt-codex/STATE.json`,
`.gpt-codex/evidence/**`, `dist/**`, any Group C path, or any Plugin path.

Its authorized actions are exactly `READ`, `TEST`, `VALIDATE`, `REPORT`, and
`MUTATE_APPROVED_SCOPE`. `COMMIT`, `PUSH`, `PUBLISH`, `AUTHORIZE`, and
`SCOPE_EXPANSION` are forbidden. Candidate packaging, commit, and transport
remain in the later normal reviewed candidate lifecycle; publication remains
under the existing publication authority.

The future goal is: prepare and validate exactly the v2.7.3 release candidate
metadata/source surface after B1–B6 closure, without changing Contract Repair
technical semantics or publishing the release.

Its acceptance binds:

```text

```

Kernel version is unchanged unless independently required; Tasks 5–9 semantics,
B6 clean-room proof, no Group C, no Plugin, and no bridge reuse are unchanged.

## 3. Non-recursive governance first

Phase 1 is governance artifact acceptance. This Design amendment and a future
Plan amendment must each pass the existing lifecycle:

```text
candidate artifact
-> independent review
-> GPT adjudication
-> exact USER acceptance
-> durable integration
-> immutable commit/path refs
```

Only when both accepted amendment artifacts are durably resolvable may Phase 2
begin. `BOOTSTRAP_CANNOT_AUTHORIZE_ITS_OWN_DESIGN_OR_PLAN = YES`. The bootstrap
must never create, modify, integrate, or approve its own Design or Plan
authority source.

materializing the frozen Work Unit. It is not a bridge and must not be called
`bridge-006`.


Its exact mutation path is
`.gpt-codex/work-units/framework-v2.7.3-release-001.json`; its sole operation
is `CREATE_ONLY`. If that path already exists, the outcome is
`RECONCILIATION_REQUIRED`; overwrite is prohibited.

The bootstrap lifecycle is exactly:


## 6. Publication and finalization remain separately governed

The preserved lifecycle is:

```text
release Work Unit implementation
-> focused/full verification
-> independent POST_EXECUTION review
-> GPT adjudication
-> exact USER candidate acceptance
-> candidate packaging/integration
-> publication preflight
-> TAG_WRITE / RELEASE_WRITE / ASSET_UPLOAD
-> remote verification
-> publication Result/Evidence
-> State finalization
```

Neither the future release Work Unit nor the bootstrap authorizes publication.
After remote publication, `.gpt-codex/STATE.json`, publication verification
Evidence, and publication Result remain under the separately valid existing
publication/State-finalization lifecycle. They are deliberately absent from the
nine-path Work Unit scope.
