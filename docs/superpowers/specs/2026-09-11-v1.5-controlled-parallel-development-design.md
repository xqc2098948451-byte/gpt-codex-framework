# GPT–Codex Framework v1.5 Controlled Parallel Development Design

## Purpose

Increase Codex throughput without weakening task, Git, review, handoff, or user-approval boundaries. Parallelism is confined to independent execution units inside one approved parent task.

## Design

- Default policy: `AUTO_SAFE`; maximum 3 simultaneous implementation workers.
- One parent task remains the source of scope, final Implementation SHA, Fresh Review, and integration authority.
- Parallel units are scheduled in dependency waves and require explicit dependencies, owned paths, independent verification, and isolated Git worktrees/branches.
- Shared mutable hotspots default to serial ownership.
- Worker commits are durable execution evidence only. `PARALLEL_COMPOSE` combines approved child commits into the parent task branch, followed by full parent verification; the resulting parent state receives the semantic Implementation SHA.
- Partial failures preserve successful independent unit work but block dependent composition.
- Cross-worker/base/ownership/compose conflicts enter `PARALLEL_RECONCILIATION_REQUIRED`.

## User-facing scheduling contract

GPT must explicitly declare before every copyable Codex command:

- `【执行策略】串行（SERIAL） | 并行（PARALLEL）`
- `【完成后是否需要批准】不需要 | 需要 GPT 判断 | 需要用户批准`

Machine fields remain `EXECUTION_STRATEGY` and `COMPLETION_GATE`. `NONE` never waits for user confirmation; `GPT_DECISION` requires relay to GPT but not user approval; `USER_APPROVAL` is explicit-only.

## Non-goals

- Running unrelated top-level tasks concurrently.
- Raising the normal worker limit above 3.
- Allowing parallel workers to share one writable worktree.
- Letting worker commits independently become final task review/integration identities.
- Expanding push/merge/history-rewrite permissions.
