# v2.2.1 Consumer Projection Release Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unsafe repository-wide release walk with a validated, positive consumer projection that produces a new consumer-safe v2.2.1 artifact while preserving the complete Management Repository and its historical audit records.

**Architecture:** Add an exact JSON path-classification manifest and a focused projection module. The release pipeline audits the complete source, copies only `CONSUMER_REQUIRED` files into a temporary staging root, validates that root, and then uses the existing deterministic ZIP writer; Management Validator and Consumer Projection Validator remain separate checks.

**Tech Stack:** Python 3, `pathlib`, `zipfile`, `tempfile`, `hashlib`, JSON Schema v1, `unittest`, existing `.gpt-codex/scripts/release_framework.py` pipeline.

**Spec:** `docs/superpowers/specs/2026-09-11-v2.2.1-consumer-projection-release-boundary-design.md`

## Global Constraints

- Keep `VERSION` at `2.2.1`, `KERNEL_VERSION` at `2.0.0`, and `SCHEMA_VERSION` at `1`.
- Treat `02171f7984d7409ce945ebb26154f216ff63027bbc35fcf1d3d99ad8ff2806c6` as `REJECTED_FOR_CONSUMER_CONTAMINATION`, never as a formal release SHA.
- Keep the v2.2.0 artifact and historical metadata immutable.
- Never rewrite historical `docs/superpowers/specs/**` or `docs/superpowers/plans/**` content.
- Consumer inclusion is exact positive allowlist only; unknown/unclassified non-local paths default to `EXCLUDE_AND_FAIL`.
- The complete Management Repository may contain real Management identity; the Consumer Projection and ZIP may not.
- Do not copy `CONTROL.json`, `STATE.json`, Management Evidence/Result, real Management identity, Git metadata, caches, temporary files, secrets, or old release ZIPs into the projection.
- Keep W/P attestation semantics unchanged; implementation/repackage remains local-only until GPT accepts the new artifact SHA.
- Use TDD: each production change starts with a failing test, then the smallest implementation, then focused and full verification.
- Do not commit or push during this design/review work unit; those are steps for the later implementation/publication authorization.
