# GitHub-backed Project Continuity & Coordination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub repository binding, cross-window resume, local/remote sync preflight, and a fail-closed commit-push-verify result gate while preserving the v2.1 Kernel and Schema contracts.

**Architecture:** Bind one project context to one GitHub repository through the existing authoritative `CONTROL.json`, record remote freshness in the existing `STATE.json`, and keep Result Envelope as the machine Source of Truth. Extend the existing controlled Git lifecycle with an explicit continuity publication gate and local degradation; do not add a pointer, registry, daemon, or second state machine.

**Tech Stack:** Python standard library scripts/tests, JSON Schema generation 1, Markdown governance artifacts, local Git CLI, optional GitHub CLI/API capability detection, deterministic ZIP packaging.

**Spec:** `docs/superpowers/specs/2026-09-11-v2.2.0-github-project-continuity-design.md`

## Global Constraints

- Framework release target is `2.2.0`; do not begin implementation until the exact Design and Plan files are approved and hash-bound.
- `KERNEL_VERSION` remains `2.0.0`; `.gpt-codex/KERNEL.md` is never modified.
- `SCHEMA_VERSION` remains `1`; all envelope, CONTROL, STATE, and Result changes are additive/conditional.
- One governed project has exactly one `PROJECT_CONTEXT_ID` and one GitHub `repository_id`; monorepo routing is out of scope.
- `cross-project-context-binding` remains required; repository binding is added before any GitHub-continuity mutation.
- `CONTROL.github.repository_id` is the machine repository identity; full name is diagnostic/access metadata and path/URL is never identity.
- Formal `PASS` requires authorized commit, successful push, and independent remote verification; local completion without those facts is `LOCAL_COMPLETE` with `SYNC_PENDING`.
- GitHub outage permits local tests and commits but never a formal `PASS` and never claims the local state is remotely recoverable.
- Dirty, ahead, behind, divergent, stale, foreign, or ambiguous repositories require reconciliation and cannot be overwritten automatically.
- No repository creation, remote replacement/deletion, force push, history rewrite, stash-as-hiding, GitHub Actions, Codespaces, paid service, credential persistence, or consumer-project mutation is allowed by default.
- Existing v2.1 tests, bootstrap challenge, context binding, return rendering, release packaging, and Kernel conformance must remain green.

## File map and implementation boundaries

The implementation uses these exact repository paths:

- `.gpt-codex/scripts/github_repository_binding.py` owns canonical GitHub identity, remote resolution, binding comparison, and compatibility scan.
- `.gpt-codex/scripts/git_continuity.py` owns local/remote snapshot comparison, preflight outcomes, publish gating, and remote verification evidence normalization.
- `.gpt-codex/scripts/continuity_resume.py` owns read-only GPT resume loading from canonical CONTROL/STATE/Work Unit/Evidence/Result references.
- `.gpt-codex/scripts/instruction_envelope.py` and `.gpt-codex/scripts/result_return.py` remain the only envelope/rendering implementations.
- `.gpt-codex/builtins/guardrails/github-repository-binding/` contains repository identity/push safety instructions and manifest.
- `.gpt-codex/builtins/skills/github-project-continuity/` contains resume, preflight, publication, offline, and result instructions.
- Existing `.gpt-codex/builtins/skills/git-basic/` remains the low-level optional Git Skill; it is extended only where needed to reference the continuity gate.
- `.gpt-codex/evidence/results/` is the existing Evidence namespace’s result subdirectory; it is not a new authority or pointer subsystem.
- Existing schema, template, validator, migration, README, bootstrap, changelog, and release files are extended in place.

### Shared interfaces

The implementation must expose and reuse these typed contracts:

```python
# .gpt-codex/scripts/github_repository_binding.py
@dataclass(frozen=True)
class RepositoryBinding:
    repository_id: str
    repository_full_name: str
    default_branch: str

@dataclass(frozen=True)
class ObservedRepository:
    repository_id: str
    repository_full_name: str | None
    local_remote_name: str
    canonical_remote: str

@dataclass(frozen=True)
class BindingDecision:
    decision: str
    reason: str
    identity_match: bool
    mutation_allowed: bool

def canonicalize_remote_url(url: str) -> str: ...
def compare_repository_binding(control: Mapping[str, Any], observed: ObservedRepository) -> BindingDecision: ...
def scan_repository_compatibility(repo_root: Path, github_metadata: Mapping[str, Any] | None) -> dict[str, Any]: ...

# .gpt-codex/scripts/git_continuity.py
@dataclass(frozen=True)
class SyncSnapshot:
    local_head_sha: str | None
    remote_head_sha: str | None
    remote_ref: str | None
    dirty: bool
    local_ahead: int
    remote_ahead: int
    diverged: bool

@dataclass(frozen=True)
class SyncDecision:
    decision: str
    reason: str
    mutation_allowed: bool
    publish_allowed: bool

def evaluate_sync_preflight(snapshot: SyncSnapshot, expected_base_sha: str | None, expected_remote_ref: str | None, expected_remote_head_sha: str | None, expected_state_revision: int, current_state_revision: int) -> SyncDecision: ...
def evaluate_new_work_preflight(snapshot: SyncSnapshot, expected_base_sha: str | None, expected_remote_ref: str | None, expected_remote_head_sha: str | None, expected_state_revision: int, current_state_revision: int) -> SyncDecision: ...
def evaluate_active_work_degraded_continuation(identity_validated: bool, initial_clean_sync: bool, authorized_active: bool, remote_available: bool, requested_new_work_unit: bool) -> SyncDecision: ...
def evaluate_publish_gate(binding: BindingDecision, sync: SyncDecision, push_status: str, remote_verification: str, state_revision_match: bool) -> SyncDecision: ...
def verify_remote_publication(remote_ref: str, expected_publication_commit: str, observed_repository_id: str, bound_repository_id: str, object_reachable: bool) -> dict[str, Any]: ...

# .gpt-codex/scripts/continuity_resume.py
def load_continuity_resume(repo_root: Path, selected_repository_id: str) -> dict[str, Any]: ...
```

Later tasks consume these names exactly; changing them requires updating this
plan and re-running plan self-review before implementation.
