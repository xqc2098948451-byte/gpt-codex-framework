# GPT–Codex Framework v2.0.3 Paste-ready Return and Fixed Source Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Framework v2.0.3 with a Result Envelope-derived paste-ready GPT return contract and a fixed unversioned auxiliary Framework Source Folder convention.

**Architecture:** Add one small standard-library formatter module under the existing framework scripts. It accepts the existing machine Result Envelope and derives deterministic plain text; no second state or evidence store is introduced. Extend the existing envelope schema/template, handoff instructions, consumer workspace documentation, validator checks, release metadata, and tests while leaving the Kernel Contract files unchanged.

**Tech Stack:** Python 3 standard library, unittest, JSON Schema-shaped contract files, Markdown documentation, deterministic ZIP release script.

**Spec:** `docs/superpowers/specs/2026-09-11-v2.0.3-paste-ready-return-and-fixed-source-design.md`

## Global Constraints

- Framework Release Version is `2.0.3`.
- Kernel Version remains `2.0.0`.
- Schema Version remains `1`.
- `.gpt-codex/KERNEL.md` and `.gpt-codex/scripts/kernel_rules.py` must remain byte-for-byte unchanged.
- Existing historical specs/plans and release records must not be modified or deleted.
- The machine Result Envelope remains the only source of structured facts; GPT Return Text is derived only from it.
- Consumer projects use a fixed unversioned Framework Source Folder; Project is authoritative and Framework is advisory.
- `dist/` must contain only v2.0.3 release artifacts after the release Skill runs.
