# GPT–Codex Framework v2.0 Minimal Kernel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the v2.0 bootstrap distribution with a minimal machine-verifiable Kernel, curated Built-ins, dual-root project templates, Harvest workflow, compatibility/migration flow, and preserved v1.x framework history.

**Architecture:** The distribution separates Kernel contracts from Built-ins and project-local extensions. JSON is the machine authority for control/state/work/evidence/extension contracts; Markdown explains human intent. A Python standard-library validator and conformance suite enforce critical Kernel invariants without introducing a new policy language.

**Tech Stack:** Markdown, JSON, Python 3 standard library, ZIP distribution.

**Spec:** `docs/superpowers/specs/2026-09-11-v2.0-minimal-kernel-design.md`

## Global Constraints

- Project root is authoritative; framework root is auxiliary.
- Framework Kernel/Built-ins are read-only during ordinary project execution.
- Preinstalled Built-ins are not automatically enabled.
- Project-specific extensions require evidence/provenance and are exported only as Harvest Candidates.
- Framework upgrades are evaluated, not propagated.
- Existing v1.x spec/plan history is preserved unchanged.
- Human-facing Codex execution strategy and approval fields remain Chinese.
