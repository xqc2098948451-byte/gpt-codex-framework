# B7 v2.7.3 Publication Packaging Authority Design Correction

## Status and purpose

This is a Design-only correction candidate. It resolves the already
identified contradiction between the accepted B7 v2.7.3 publication-plan
interpretation that the release artifacts are generated/untracked only and
the production publication contract that requires an immutable Git-object
canonical artifact. It neither creates implementation authority nor changes
the production publication contract.

The correction adopts `SEPARATE_BOUNDED_PUBLICATION_PACKAGING_LIFECYCLE`.
It supersedes only the B7 Design/Plan interpretation for the v2.7.3
publication artifact that says the three v2.7.3 `dist/` artifacts are
"generated untracked only." It does not rewrite any historical file.

The current `framework-v2.7.3-release-001` Work Unit cannot cure either
contradiction: it owns only the original nine source paths; it owns neither
the projection manifest nor `dist/**`; and it cannot expand its own scope.

## Two immutable candidates

`S` remains the exact USER-accepted v2.7.3 source candidate described above.
The later `W` is a distinct, future publication-packaging candidate commit.
`W` must be a verified descendant of `S`; `S` is
`d9dd439a6d6ca944a6f07ed1aa0b386b0ac0a0b7`. `W` need not be a direct child
of `S`: accepted Design correction, Plan correction, and packaging Work Unit
commits may be independently governed intervening ancestry. Independent
review and exact USER acceptance of `W` are required before it may become the
tag target.

The exact packaging candidate commit that becomes `W` is scoped relative to
its immediate parent, not relative to `S`. That parent-to-`W` changed-path
set must contain exactly seven paths and must equal the frozen packaging scope
stated below; any additional mutation in the `W` packaging commit itself is
forbidden. Review must prove all of the following:

1. `S` is an ancestor of `W`.
2. All nine `S` source paths at `W` are byte-identical to their bytes at `S`.
3. `W`'s immediate parent-to-`W` changed-path count is exactly seven.
4. Those seven paths equal the frozen packaging scope.
5. Intervening governance artifacts do not expand packaging mutation
   authority.

`git diff S..W` is not required to contain only seven paths and must not be
used to reject independently governed intervening artifacts.

The canonical artifact reference at that future point is
`W:dist/gpt-codex-framework-v2.7.3-bootstrap.zip`. The annotated `v2.7.3`
tag must target the exact accepted `W`, never source-only `S`. Before tagging,
verification must prove that `S` is an ancestor of `W` and that the nine
source-path bytes in `W` equal their bytes in `S`.

### Artifact materialization semantics

Packaging must not regenerate the USER-accepted ZIP. It must materialize the
exact accepted Phase-F ZIP bytes with SHA-256
`8da1be98f9d7ea18fb3008685331956dfcb2232ac1ccfdf9085dd466a793a39d` and
size `139774` into future `W`. The sidecar and release JSON must derive from
the same Phase-F validation output and must be independently verified during
review of `W`. If the accepted ZIP bytes cannot be obtained, or either hash or
size differs, the outcome is `RECONCILIATION_REQUIRED`; running a generator
to produce an equivalent-but-different artifact is prohibited.

`bootstrap/framework-v2.7.3-release-work-unit-001` is already `TERMINATED`.
It must never be reused and cannot create a second Work Unit. Since production
has no ordinary self-creation authority for Work Units, the dedicated
packaging Work Unit requires a new B7-specific, one-time external bootstrap
lifecycle:

| Field | Exact value |

| `REMOTE_REF` | `refs/tags/bootstrap/framework-v2.7.3-publication-packaging-work-unit-001` |

| `operation` | `CREATE_ONLY` |
| mutation path | only `.gpt-codex/work-units/framework-v2.7.3-publication-packaging-001.json` |

This is a new object, not reuse of the old bootstrap. It creates neither a
generic Work Unit factory nor a general bootstrap precedent. Its exact payload

approval, an immutable annotated tag, and exact Work Unit materialization.
After independent verification and exact Work Unit integration, this bootstrap
is `TERMINATED` and may not be used a second time.

1. accepted Design correction;
2. USER acceptance;
3. durable integration;
4. independent remote verification;
5. accepted Plan correction;
6. USER acceptance;
7. durable integration;
8. independent remote verification;
9. fresh repository, `main`, and State observation;
10. freeze `expected_base_sha`; and

`origin/main` only after both accepted correction artifacts are durably

`RECONCILIATION_REQUIRED`.
