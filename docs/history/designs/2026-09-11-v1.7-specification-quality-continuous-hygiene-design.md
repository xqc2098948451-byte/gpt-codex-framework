# GPT–Codex Framework v1.7 — Specification Quality & Continuous Hygiene Design

## Goal
Close the v1.x line by adding requirement-quality, artifact-consistency, convergence, and continuous codebase-hygiene controls without performing the v2.0 modular architecture rewrite.

## Design
1. Clarify material ambiguity before planning/implementation; persist only when useful.
2. Test requirement quality with a checklist distinct from implementation tests.
3. Add read-only ARTIFACT_ANALYSIS before meaningful governed implementation.
4. Add read-only CONVERGENCE_CHECK after Fresh Review for material feature completion.
5. Encode approved project engineering taste in Golden Principles; scan drift continuously and repair only through scoped hygiene authority.
6. Use progressive disclosure and optional feature packages to keep context bounded.
7. Freeze v1.x capability growth after v1.7 and record structural ideas in V2_ROADMAP.md.

## Safety boundaries
- Existing repository patterns are not automatically approved patterns.
- Hygiene cannot hide product/architecture/schema/dependency changes.
- Analysis/convergence/quality scan are read-only.
- New gaps create flow-forward work; historical task/review evidence is not rewritten.
- All prior Bootstrap/Git/Parallel/Observability/Action-Routing/Handoff invariants remain intact.
